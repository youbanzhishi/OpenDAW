# ADR-008: Person Agent Schema — 人的数字身份协议

## 背景
主人希望"一条链接就够了"——把链接发给任何AI，AI就知道往哪搜博客、从哪取视频、用什么风格交流。更进一步，未来人形机器人扫二维码就能完成身份识别和交互初始化。

当前问题：主人的数字身份散落在各处（博客/知识库/保险箱/服务器），每个AI都要重新教一遍。OpenLink已有agent发现和身份卡片功能，但只面向AI Agent，不面向人。

## 决策
在OpenLink中实现`/.well-known/agent.json`端点，定义Person Agent Schema——人的数字身份协议。

核心设计：
1. **分层暴露**：公开层（谁都能看）/ 授权层（需验证）/ 私密层（永远不暴露，通过代理）
2. **代理授权**：私密数据不直接暴露，通过主代理（小龙）间接访问
3. **双消费模式**：人看身份卡片，AI读agent.json协议
4. **二维码映射**：二维码=OpenLink入口URL，扫一下就行

## 理由
- 不起新项目：OpenLink已有短链+身份卡片+agent发现+P2P+插件系统，只缺一层胶水
- 分层暴露是必须的：全部公开=隐私泄露，全部封闭=无法发现
- 代理授权比OAuth轻量：不需要外部AI去注册应用、走授权流程，通过主人信任的代理就行
- agent.json是业界标准（Well-Known URI），AI天然理解

## 后果
- 正面：一条链接打通所有服务，新AI零学习成本，二维码赋能人形机器人交互
- 负面：OpenLink成为单点，挂了=身份不可发现（需要边缘缓存/离线方案）
- 风险：公开层信息可能被爬取（解决方案：公开层只放必要的身份声明）
- 未来：可能需要标准化Person Agent Schema，让更多平台支持
